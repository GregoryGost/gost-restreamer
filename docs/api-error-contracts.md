# Причины ошибок управляющего API

Ошибочный HTTP-запрос получает `application/problem+json` со стандартными полями Problem Details и обязательным `code`. `detail` объясняет причину по-русски. Отдельное необязательное `action` подсказывает следующий шаг; клиент показывает его отдельно и не выполняет автоматически. Тексты могут уточняться, поэтому программная обработка использует код. Примеры работы клиента приведены в [руководстве OBS](obs-client-guide.md#отказы-запуска).

Необязательное `field` содержит проверенное публичное имя поля запроса или объекта. Необязательный `context` содержит только известные строковые идентификаторы: `stream_id`, `session_id`, `output_id`, `group_id`, `profile_id`, `asset_id`, `generation_id`, `variant_id`, `destination_id`, `command_id`. Пустые сведения опускаются. Запрошенный ID отсутствующего объекта не отражается как подтверждённый контекст. Ключи, URL, пути, имена объектов, значения `request_id`, служебные токены и признаки владения, произвольные исключения в объяснения не попадают. Значения ожидаемого и фактического формата или параметров в контекст не добавляются.

Классификация HTTP сохраняет прежние приоритеты. Подробная причина выбирается после неё, только из совместимой проверенной ветви. Несогласованные причины одного класса дают общий ответ этого класса; данные разных ветвей не смешиваются. Неожиданный `500` получает `internal_error` без подробностей внутреннего исключения и без подсказки действия. Исходная диагностика остаётся в локальном журнале приложения по действующей политике `full`.

## Отказ до принятия команды

| Код | Доказанная причина | Действие клиента |
| --- | --- | --- |
| `fallback_not_configured` | Для запуска не выбрана политика заглушки. | Настроить политику с выбранной заглушкой. |
| `fallback_not_prepared` | У выбранной заглушки нет опубликованного готового поколения. | Завершить загрузку и подготовку. |
| `fallback_profile_not_prepared` | В текущем поколении отсутствует вариант точного полного профиля группы. | Повторно подготовить заглушку для сохранённого профиля и дождаться готовности. |
| `fallback_variant_not_ready` | Конкретный выбранный или закреплённый вариант непригоден для запуска. | Проверить состояние варианта и журнал; новый вариант не заменяет прежний OutputSnapshot. |
| `preparation_active` | Активная подготовка исключает запуск. | Дождаться её завершения. |
| `session_active` | Stream уже занят нетерминальным запуском. | Прочитать текущую сессию. |
| `request_id_conflict` | Прежний `request_id` принадлежит другому смысловому запросу. | Читать прежнюю квитанцию; для нового действия выбрать новый `request_id`. |
| `revision_conflict` | Ожидаемая ревизия не совпала с текущей. | Заново прочитать объект и передать его актуальную ревизию. |
| `session_state_conflict` | Состояние Session не допускает команду. | Прочитать Session перед следующим действием. |
| `output_detached` | Выход уже отсоединён. | Для нового выхода явно добавить назначение. |
| `output_already_running` | Для выхода уже задано намерение работы. | Проверить выход и прежнюю команду. |
| `output_cleanup_pending` | Очистка прежнего выполнения выхода не подтверждена. | Дождаться подтверждённой очистки. |
| `destination_attached` | Назначение уже прикреплено к Session. | Использовать существующий выход. |
| `resource_in_use` | Объект используется сохранёнными связями или удерживаемыми ресурсами. | Проверить связанные объекты и активные сессии. |
| `resource_ownership_conflict` | Прочитанные объекты имеют несовместимую принадлежность. | Выбрать связанные объекты одного Stream/Session. |

Эти различия не меняют допуск запуска. Сервер не исправляет настройки, не готовит заглушку и не повторяет команду вследствие ошибки. Изменение только битрейта или preset также меняет полный профиль: совпадение `MediaFormat` не доказывает пригодность прежнего варианта. HTTP start не получает реальный поток OBS и не может по этому отказу установить несовместимость фактического LIVE.

## Разбор запроса и инфраструктура

| HTTP | Коды | Значение и следующий шаг |
| --- | --- | --- |
| `400` | `invalid_json`, `invalid_request` | Проверить структуру JSON или параметры по схеме операции. |
| `400` | `invalid_cursor` | Начать чтение с новой границы и использовать полученный cursor. |
| `400` | `invalid_time` | Передать известную временную границу `from` или `to` в формате RFC3339Nano. |
| `400` | `sse_cursor_conflict` | Передать одну позицию либо одинаковые cursor и Last-Event-ID. |
| `404` | `resource_not_found` | Проверить вид и идентификатор запрашиваемого объекта. Неизвестный присланный ID в контекст не копируется. |
| `404` | `nested_resource_not_found` | Проверить список объектов и принадлежность родителю. |
| `404` | `route_not_found`, `schema_not_found` | Использовать маршрут или ссылку на схему из OpenAPI. |
| `405` | `method_not_allowed` | Использовать объявленный для маршрута HTTP-метод. |
| `408` | `body_read_timeout`, `upload_timeout` | Проверить передачу тела или файла клиентом; при загрузке также состояние поколения. |
| `408` | `upload_canceled` | Передача файла отменена; проверить состояние поколения перед новой загрузкой. Сохраняется прежнее отображение этого отказа в `408`. |
| `409` | `state_conflict` | Общий отказ состояния или версии без однозначной предметной причины; прочитать актуальное состояние. |
| `409` | `credential_commit_unknown` | Отменить принятую запись полномочий чата уже нельзя, её исход не подтверждён. GET попытки сообщает тот же код при `200 PENDING`. |
| `412` | `precondition_failed` | Условный запрос к встроенному ресурсу документации не выполнен. Проверить условные заголовки запроса. |
| `413` | `body_too_large` | Уменьшить доказанно слишком большое тело. |
| `413` | `preparation_limit`, `request_limit` | Проверить ограничения операции, исходного материала и подготовки. Этот статус сам по себе не доказывает превышение размера HTTP-тела. |
| `415` | `unsupported_media_type` | Передать Content-Type из схемы операции. |
| `416` | `range_not_satisfiable` | Запрошенный диапазон байтов встроенного ресурса недоступен. Проверить его границы по размеру файла. |
| `422` | `invalid_parameters`, `invalid_field` | Проверить параметры или указанное публичное поле по схеме. |
| `422` | `empty_upload` | Передать непустой файл изображения либо видео. |
| `422` | `invalid_profile`, `invalid_custom`, `duplicate_custom`, `custom_conflict`, `unknown_custom` | Исправить указанное поле полного профиля; прежние подробные code/field/detail сохраняются. |
| `503` | `service_unavailable`, `api_closed`, `service_busy` | Проверить готовность управления и текущее состояние. |
| `503` | `runtime_unavailable`, `resource_limit` | Проверить возможности сервера и локальный журнал. |
| `503` | `operation_canceled`, `operation_timeout` | Прочитать состояние объекта и известную принятую квитанцию; не считать отмену запроса доказательством отмены команды. |
| `503` | `sse_client_limit`, `sse_transport_unavailable` | Закрыть ненужные подписки либо проверить поддержку SSE и сроков записи транспортом. |
| `500` | `internal_error` | Общее внутреннее исключение; доверенной подсказки действия в ответе нет. |

Тексты и значения автоматической валидации Huma не являются публичной диагностикой. Путь поля допускается только после сверки с публичной схемой текущей операции; неизвестные имена и динамические ключи не повторяются. Ошибки до обработчика, прямые ответы маршрутизатора и SSE до начала передачи используют тот же формат. После открытия SSE HTTP-статус уже не меняется; действует предусмотренный управляющий кадр или закрытие соединения.

## Результат принятой команды

`202 Accepted` подтверждает долговечное принятие. Итог читается по `Location` квитанции независимо от SSE. Успешный `GET /commands/{commandId}` возвращает `200` и для `FAILED`/`INTERRUPTED`. Внутри `failure` сохраняются поля `code` и `message`; отдельные `action`, `field`, `context` имеют ту же семантику, что в Problem Details. При отсутствии отказа весь `failure` равен `null`.

Доказанная предметная причина, например `fallback_variant_not_ready`, сохраняет свой код. Когда известен только отказ этапа исполнения, используются следующие коды без предположений о GPU, сети или первопричине нативного процесса:

| Код | Известный этап |
| --- | --- |
| `session_start_failed`, `output_start_failed` | Не удалось выполнить запуск Session либо выхода. |
| `session_stop_failed`, `output_stop_failed` | Не удалось завершить остановку Session либо выхода. |
| `session_pause_failed`, `session_resume_failed` | Не удалось применить паузу либо возобновление. |
| `execution_interrupted` | Прежний владелец исполнения потерян. |
| `command_superseded` | Последующее управление прервало незавершённую команду. |

Клиент показывает подготовленные причину и действие, читает актуальное состояние и при необходимости локальный журнал. Новый запуск требует отдельного явного действия. Прежний успешный результат не переписывается поздним отказом исполнения.

Код и известный контекст сохраняются атомарно с результатом, независимо от последующих настроек. Повтор того же смыслового запроса с тем же `request_id` возвращает прежнюю квитанцию. Старые результаты без типизированной причины получают прежние общие `session_failed`, `session_interrupted`, `command_failed`, `command_interrupted`; произвольная историческая диагностика не раскрывается. Подготовка и оперативные наблюдения сохраняют общие `preparation_failed`, `preparation_interrupted`, `observation_failed`.

Внутри поддерживаемого формата записи без `FailureReason` читаются; отсутствие поля не является повреждением. `MetadataVersion=1` и история Goose имеют самостоятельное назначение и не обещают двусторонней совместимости бинарников. Текущий `storage_format=5` рассчитан на новую установку; БД прежних форматов отклоняются без преобразования. Полные ограничения описаны в [контракте хранения](domain-storage-contracts.md#граница-долговечных-данных-и-оперативного-состояния).
