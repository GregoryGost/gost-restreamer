# gost-restreamer

Сервис для самостоятельного размещения и одновременной трансляции одного потока из OBS на несколько стриминговых площадок.

Планируются независимое управление выходами, перекодирование на сервере под требования площадок и автоматическое переключение на подготовленную заглушку при потере источника.

Исполняемый сервис ещё не реализован. В `internal/core` и `internal/media` добавлены общие типы форматов, профиля группы, неизменяемого пакета и конфигурации дорожки, а также валидация настроек очередей и watchdog. Для этой основы используются стандартная библиотека Go, unit-тесты и синтетические данные; остальные компоненты приложения ещё предстоит реализовать.

## Среда разработки

Нужны Go `1.27.3`, GNU Make и C-компилятор. На macOS используется компилятор из Command Line Tools. CGO включён для выбранного SQLite-драйвера; серверная сборка предназначена для Debian 13 / `linux/amd64`.

Версия Go задаётся в `go.mod`, версия `golangci-lint` — в `Makefile`. Команды Make проверяют точную версию Go и используют `GOTOOLCHAIN=local`, `GOWORK=off`, `CGO_ENABLED=1`; автоматическая загрузка другого Go SDK отключена.

```sh
make tools
make bootstrap-check
```

`make tools` собирает `golangci-lint` версии `2.15.0` в `bin/` этого репозитория. Команда использует сеть и стандартные кэши Go, но не устанавливает бинарник глобально и не добавляет зависимости линтера в основной `go.mod`.

`bootstrap-check` проверяет версию Go, форматирование, согласованность модуля, целостность загруженных модулей и конфигурацию линтера. Полная команда `make check` дополнительно проверяет существующие пакеты: vet, lint, unit-тесты, race и сборку. Проверки общих контрактов не подтверждают работу ingest, FFmpeg, переключения или отправки на площадки.

## Команды

| Команда | Действие |
| --- | --- |
| `make help` | Показать основные команды. |
| `make tools` | Установить закреплённый линтер в `bin/`. |
| `make bootstrap-check` | Проверить основу проекта, включая репозиторий без Go-пакетов. |
| `make fmt` / `make fmt-check` | Применить `gofmt` / проверить форматирование без изменения файлов. |
| `make tidy` / `make tidy-check` | Обновить `go.mod`/`go.sum` по импортам / показать необходимые изменения с ошибкой при расхождении. |
| `make mod-verify` | Проверить целостность модулей в кэше Go. |
| `make vet` / `make lint` | Выполнить `go vet` / выбранные проверки `golangci-lint`. |
| `make test` / `make test-race` | Выполнить тесты / тесты с детектором гонок. |
| `make build` | Собрать Go-пакеты. |
| `make check` | Проверить основу, выполнить анализ, тесты, проверку гонок и сборку пакетов. |
| `make binary` | Собрать `bin/gost-restreamer` после появления точки входа `cmd/gost-restreamer/`. |

Файл `.golangci.yml` включает только `errcheck`, `govet`, `ineffassign`, `staticcheck` и `unused`. Версия инструмента проверяется перед запуском. Отдельный автоматический линтер естественного языка не используется; проектные комментарии и документация пишутся по-русски согласно `CODEX_PROJECT.md`.

`make binary` собирает бинарник для текущей платформы. Сборка для Debian выполняется в Linux CI с включённым CGO. Для сборки с macOS под Linux потребуется настроенный C cross-compiler; одного задания `GOOS`/`GOARCH` недостаточно.

## Зависимости приложения

Модуль пока не содержит runtime-зависимостей. Они добавляются по конкретным проверенным тегам вместе с использующим их кодом:

| Область | Выбранные модули или кандидат |
| --- | --- |
| Медиатракт | `github.com/bluenviron/gortmplib` — кандидат, требующий проверки Enhanced RTMP и forwarding. |
| Хранение | `gorm.io/gorm`, `gorm.io/driver/sqlite`, `github.com/pressly/goose/v3`. |
| HTTP API | `github.com/danielgtaylor/huma/v2`, `github.com/go-chi/chi/v5`. |
| Локальный кэш | `github.com/maypok86/otter/v2`, когда определён полезный сценарий чтения. |

Перед выбором тега проверяются требования его `go.mod` и совместимость с остальным стеком. После добавления импортов выполняются `make tidy` и проверки. Созданный `go.sum` хранится в Git; пустой файл заранее не создаётся. YAML-библиотека и адаптер медиаконтейнера ещё не выбраны.

## CI

[Workflow](.github/workflows/go.yml) запускается на `push` и `pull_request`. Он настроен проверять основу и существующие Go-пакеты; при отсутствии пакетов сообщает о пропуске их анализа, тестов и сборки. Точки входа `cmd/gost-restreamer/main.go` пока нет, поэтому бинарник сервиса, архив и SHA-256 не создаются.

Обязательный CI работает без FFmpeg, GPU и внешних стриминговых площадок. Устройство среды и границы проверок описаны в [.github/README.md](.github/README.md). Бинарники и архивы сохраняются в `bin/` и `dist/`, исключённых из Git.
