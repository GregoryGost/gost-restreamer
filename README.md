# gost-restreamer

Сервис для самостоятельного размещения и одновременной трансляции одного потока из OBS на несколько стриминговых площадок.

Проект предусматривает независимое управление выходами, перекодирование на сервере под требования площадок и автоматическое переключение на подготовленную заглушку при потере источника.

По проектному контракту управляющий API, SSE, OpenAPI/docs/schema и health используются в локальной сети владельца без авторизации и токенов доступа. Приём OBS проверяет постоянный ключ Stream и наличие активной Session.

Исполняемый сервис ещё не собран. `internal/core` и `internal/storage` содержат домен, операции сессий, сохраняемые команды, восстановление и общую authority runtime-допуска поверх GORM/SQLite/Goose. Текущие наблюдения Session/Group/Output/FFmpeg отделены в ограниченный RAM-реестр с точными владельцами и поколениями. В `internal/media` находятся Packet Router, raw Enhanced RTMP ingest, fMP4-адаптер и FFmpeg Supervisor с UDS; NVIDIA-команда задаёт выходное разрешение и FPS по профилю. Пакеты `internal/fallback` и `internal/media/group` содержат принятую локальную реализацию подготовки поколений заглушки, групп и Switcher. Publishers, API и точка входа остаются следующими задачами. Проверки используют синтетические данные, временные файловые БД и локальные сокеты; медиапроверки FFmpeg запускаются отдельно.

## Среда разработки

Нужны Go `1.27.3`, GNU Make и C-компилятор. ОС разработки может быть macOS, Windows или Linux; инструменты, команды и платформозависимые проверки подтверждаются для выбранной среды. Текущая проверенная среда — macOS/arm64 с компилятором из Command Line Tools. CGO включён для выбранного SQLite-драйвера; серверная сборка предназначена для Debian 13 / `linux/amd64`.

Версия Go задаётся в `go.mod`, версия `golangci-lint` — в `Makefile`. Команды Make проверяют точную версию Go и используют `GOTOOLCHAIN=local`, `GOWORK=off`, `CGO_ENABLED=1`; автоматическая загрузка другого Go SDK отключена.

```sh
make tools
make bootstrap-check
```

`make tools` собирает `golangci-lint` версии `2.15.0` в `bin/` этого репозитория. Команда использует сеть и стандартные кэши Go, но не устанавливает бинарник глобально и не добавляет зависимости линтера в основной `go.mod`.

`bootstrap-check` проверяет версию Go, форматирование, согласованность модуля, целостность загруженных модулей и конфигурацию линтера. Полная команда `make check` дополнительно проверяет существующие пакеты: vet, lint, полный запуск тестов с точным суммарным покрытием не ниже 85%, race и сборку. Проверки общих контрактов не подтверждают работу ingest, FFmpeg, переключения или отправки на площадки.

Короткие FFmpeg-интеграции выполняются отдельно от обязательного CI. Для дополнительных аппаратных проверок можно использовать ускоритель машины разработки: например, на macOS с Apple M4 проверены CPU-декодирование AV1 через `libdav1d` и аппаратное кодирование H.264 через `h264_videotoolbox`. macOS/VideoToolbox — один из возможных вариантов; наличие такого ускорителя не требуется для разработки. Точные условия короткой проверки и её ограничения описаны в [профиле проекта](CODEX_PROJECT.md#среды-разработки-и-локальные-медиапроверки). Целевой путь NVDEC/NVENC на RTX A1000 принимается отдельно; автоматическая подмена его локальным кодировщиком в приложении не вводится.

Для полного набора CPU-интеграций нужны установленные `ffmpeg` и `ffprobe` версии `7.1.5`, кодировщики `libaom-av1`, `libsvtav1`, `libx264`, `aac` и протокол `async` для настоящего UDS-входа. Пример запуска в POSIX shell:

```sh
GOST_MEDIA_FFMPEG="$(command -v ffmpeg)" \
GOST_FMP4_FFMPEG="$(command -v ffmpeg)" \
go test -count=1 ./internal/fallback ./internal/media/fmp4 ./tests/integration
```

Без этих переменных обычные тесты пропускают только зависимые от FFmpeg CPU-сценарии. Пакеты, управляемые дочерние процессы, локальные RTMP/UDS и SQLite остаются в обычной проверке. В Codex по указанию владельца проверки T03 выполняются вне sandbox; это требуется и для доступа к настоящим локальным сокетам.

На подходящей macOS отдельная аппаратная проверка H.264 через VideoToolbox включается явно:

```sh
GOST_MEDIA_FFMPEG="$(command -v ffmpeg)" GOST_MEDIA_VIDEOTOOLBOX=1 \
go test -count=1 ./tests/integration -run '^TestAcceptanceProfileConversionCPUAndOptionalVideoToolbox$'
```

Аппаратный сценарий использует `h264_videotoolbox -allow_sw 0`; AV1-декодирование, `fps` и масштабирование в этой локальной связке выполняются на CPU. Он дополняет проверки FPS/масштаба/AAC и не подтверждает NVDEC/NVENC. Если VideoToolbox недоступен, явный аппаратный запуск сообщает об отказе, а не подменяется программным H.264. Тестовая настройка метаданных SPS не заменяет независимое сравнение всех выходных меток.

## Команды

| Команда | Действие |
| --- | --- |
| `make help` | Показать основные команды. |
| `make tools` | Установить закреплённый линтер в `bin/`. |
| `make bootstrap-check` | Проверить основу проекта, включая репозиторий без Go-пакетов. |
| `make fmt` / `make fmt-check` | Применить `gofmt` / проверить форматирование без изменения файлов. |
| `make tidy` / `make tidy-check` | Обновить `go.mod`/`go.sum` по импортам / показать необходимые изменения с ошибкой при расхождении. |
| `make mod-verify` | Проверить целостность модулей в кэше Go. |
| `make vet` / `make lint` | Выполнить `go vet` / выбранные проверки `golangci-lint`. |
| `make test` / `make test-race` | Выполнить тесты / тесты с детектором гонок. |
| `make coverage` | Выполнить свежие тесты всех пакетов `./...` и проверить точное суммарное покрытие ≥85%, без исключений. |
| `make build` | Собрать Go-пакеты. |
| `make check` | Проверить основу, анализ, полный порог покрытия, гонки и сборку пакетов. |
| `make binary` | Собрать `bin/gost-restreamer` после появления точки входа `cmd/gost-restreamer/`. |

Файл `.golangci.yml` включает только `errcheck`, `govet`, `ineffassign`, `staticcheck` и `unused`. Версия инструмента проверяется перед запуском. Отдельный автоматический линтер естественного языка не используется; проектные комментарии и документация пишутся по-русски согласно `CODEX_PROJECT.md`.

`make binary` собирает бинарник для текущей платформы. Сборка для Debian выполняется в Linux CI с включённым CGO. Для сборки с macOS под Linux потребуется настроенный C cross-compiler; одного задания `GOOS`/`GOARCH` недостаточно.

## Зависимости приложения

Зависимости хранения закреплены по проверенным тегам в `go.mod` и `go.sum`. Остальные слои подключаются вместе с использующим их кодом:

| Область | Выбранные модули или кандидат |
| --- | --- |
| Медиатракт | `github.com/bluenviron/gortmplib v1.0.1`: собственный адаптер исходных сообщений для ingest; forwarding проверяется в T05. `mediacommon/v2 v2.9.3` и `go-mp4 v1.7.1` используются для codec headers. |
| Хранение | `gorm.io/gorm v1.31.2`, `gorm.io/driver/sqlite v1.6.0`, `github.com/mattn/go-sqlite3 v1.14.22` (CGO), `github.com/pressly/goose/v3 v3.27.0`. |
| HTTP API | `github.com/danielgtaylor/huma/v2`, `github.com/go-chi/chi/v5`. |
| Локальный кэш | `github.com/maypok86/otter/v2`, когда определён полезный сценарий чтения. |

Перед выбором нового тега проверяются требования его `go.mod` и совместимость с остальным стеком. После добавления импортов выполняются `make tidy` и проверки; `go.sum` хранится в Git. Для Go ↔ FFmpeg выбран streaming fMP4 через UDS; его границы времени и проверенный режим FFmpeg описаны в [медиаконтракте](docs/media-contracts.md#контейнер-и-конкретная-граница-ffmpeg). YAML-библиотека ещё не выбрана.

Хранение открывается через `storage.Open(ctx, path, options)` с явными конечными бюджетами соединений, повторов, `ObservationLimits` и `PreparationLimits`. Один владелец получает блокировку, выполняет встроенную первичную инициализацию, проверяет `storage_format` и фиксирует прерывание прежних запусков без автоматического эфира. На текущем этапе разработки схема меняется в `00001_initial.sql`, без миграции старых БД; несовместимый формат отклоняется без автоматического пересоздания. GORM и исполнитель миграций используют один CGO `sql.DB`; перед закрытием хранилища вызывающий завершает его пользователей. `storage_format=2` включает поколения fallback и реестр принадлежащих им файлов. Неизвестное ранее выданное исполнение после рестарта блокирует новую подготовку и эфир до доверенного подтверждения физического завершения.

## Хранение заглушек

Оригиналы и готовые AV1/H.264/AAC-варианты хранятся на диске в настраиваемом каталоге данных; для Debian предусмотрен `/var/lib/gost-restreamer/`. SQLite содержит только пути, размеры, контрольные суммы, профили и данные управления. Внутри файлового корня каждому комплекту принадлежат отдельные пути `fallback/<generation-id>/`.

Загрузка заменяет явно выбранный Asset новой Generation даже при одинаковых байтах. Остальные Assets сохраняются. Успешная подготовка и проверка всего требуемого набора предшествуют смене current; ошибка сохраняет прежний комплект. Генерация и rebuild запрещены при эфире, включая ручную паузу; готовый файл воспроизводится без кодирования. Точные ограничения источников, профилей, очередей и восстановления описаны в [контрактах хранения](docs/domain-storage-contracts.md) и [медиатракта](docs/media-contracts.md).

Локальная приёмка подготовки и переключения завершена на macOS/arm64 с Go `1.27.3` и FFmpeg `7.1.5`: прошли `make check`, свежие тесты, проверки race и CPU-интеграции, покрытие 7547/8858 (85,199819%). Проверены повторная подготовка одинаковых байтов, атомарная замена/ошибки, реальные AV1/H.264/SVT, несколько петель и декодирование переходов прямого Switcher. Рабочий Group проверен на fallback; постоянные RTMP-соединения, NVIDIA/Debian/live принимаются отдельно.

После перезапуска завершённые файлы можно сверить по сохранённым размеру и хешу. Существующие частичные файлы и каталоги без восстановимого доказательства владения автоматически не удаляются; неподтверждённое выданное исполнение требует доверенного cleanup до нового эфира. Точные границы приведены в контрактах.

## CI

[Workflow](.github/workflows/go.yml) выполняет проверки и сборку только после слияния pull request в `develop` (версии разработки) или `main` (релизные версии). Пуши в ветки и теги, открытие и обновление pull request не запускают workflow; при закрытии без слияния задание пропускается. Он настроен проверять основу и существующие Go-пакеты; при отсутствии пакетов сообщает о пропуске их анализа, тестов и сборки. Точки входа `cmd/gost-restreamer/main.go` пока нет, поэтому бинарник сервиса, архив и SHA-256 не создаются.

Обязательный CI работает без FFmpeg, GPU и внешних стриминговых площадок. Устройство среды и границы проверок описаны в [.github/README.md](.github/README.md). Бинарники и архивы сохраняются в `bin/` и `dist/`, исключённых из Git.
