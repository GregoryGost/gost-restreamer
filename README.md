# gost-restreamer

Сервер рестриминга для собственной инфраструктуры: один поток из OBS, несколько независимых стриминговых площадок и подготовленная заглушка на случай потери источника.

## Возможности

- Приём AV1/AAC из OBS и отправка на RTMP/RTMPS-назначения.
- Передача AV1 без перекодирования и серверное преобразование в H.264 с разрешением, частотой кадров и битрейтом по профилю.
- Совместное использование результата перекодирования несколькими назначениями одной группы.
- Автоматическое переключение между живым источником и заглушкой с сохранением исправных исходящих соединений.
- Независимое добавление, остановка, повторный запуск и удаление выходов; отдельные очереди и переподключения для каждого назначения.
- Ручная пауза с показом заглушки, история запусков и фоновая очистка ресурсов после сбоев.

## Как устроена трансляция

OBS отправляет один поток на сервер. Группы обрабатывают его по своим профилям: передают исходное видео или перекодируют его для назначений. Несколько выходов одной группы используют один медиарезультат.

Заглушки подготавливаются до эфира из видео или изображения. Для каждого профиля сохраняется готовый вариант, который во время трансляции воспроизводится без повторного кодирования. Перед запуском проверяется готовность видео и звука заглушки выбранных групп.

Отказ или переподключение одного назначения затрагивает только его выход. После перезапуска сервера новый эфир запускается вручную; очистка ресурсов прежнего запуска выполняется в фоне независимо от нового.

## Технологии

Go, FFmpeg и SQLite с GORM/Goose. Обмен с FFmpeg идёт через Unix-сокеты в формате fMP4; исходящие RTMP/RTMPS-соединения обслуживаются в Go. Для серверного аппаратного перекодирования используется NVIDIA NVDEC/NVENC. Целевая серверная среда — Debian 13.4 (`trixie`), `linux/amd64`, домашняя VM Proxmox владельца. Сервис и дочерние процессы запускаются от root; оба бинарника устанавливаются в `/opt/gost-restreamer`.

## Среда разработки

Требуются Go `1.27.3`, GNU Make и C-компилятор; CGO используется SQLite-драйвером. Версии Go и линтера закреплены в `go.mod` и `Makefile`. Инструменты и платформозависимые возможности проверяются для выбранной ОС разработки.

```sh
make tools
make check
```

`make tools` устанавливает закреплённый `golangci-lint` в `bin/` проекта. `make check` выполняет проверку форматирования и модулей, vet, линтер, тесты, проверку покрытия не ниже 85%, race и сборку пакетов.

Для показателей NVIDIA используется NVML на Linux с CGO. На macOS сборка и обычные тесты работают без NVML; показатели NVIDIA имеют явный статус недоступности. Аппаратные показания проверяются отдельно на целевом сервере.

| Команда | Действие |
| --- | --- |
| `make help` | Список команд проекта. |
| `make fmt` / `make fmt-check` | Форматирование Go-кода / проверка форматирования. |
| `make test` / `make test-race` | Тесты / тесты с детектором гонок. |
| `make coverage` | Свежий полный набор тестов и проверка покрытия ≥85% без исключений. |
| `make vet` / `make lint` | Статический анализ. |
| `make build` | Сборка Go-пакетов. |
| `make binary` | Сборка сервиса в `bin/gost-restreamer`. |
| `make process-helper` | Сборка `bin/gost-process-helper` для управления дочерними FFmpeg/ffprobe. |
| `make package VERSION=<версия>` | Оба бинарника, пример YAML, systemd-unit, архив текущей платформы и проверенная SHA-256. |
| `make package-debian VERSION=<версия>` | GoReleaser Community `2.19.0`: `.deb`, `.tar.gz` и SHA256 для Debian 13/amd64; нужен чистый checkout с соответствующим локальным тегом. |
| `make release-check` | Проверка конфигураций GoReleaser и тесты повторного выпуска; нужны GoReleaser `2.19.0` и Node.js `24`. |

### Запуск сервиса

Собираются оба исполняемых файла:

```sh
make binary process-helper
```

Версию обоих бинарников можно прочитать без конфигурации и запуска сервиса:

```sh
./bin/gost-restreamer --version
./bin/gost-process-helper --version
```

Вывод содержит версию приложения, commit, признак локальных изменений и версию Go. Выпуски имеют вид `v0.1.0`, сборки разработки — `v0.2.0-dev.1+<commit>`. Для явно назначенной локальной версии используйте `make binary process-helper VERSION=v0.2.0-dev.1+a1b2c3d`. Без `VERSION` используются доступные метаданные Go; при их отсутствии выводится `devel` и неизвестное происхождение. Правила назначения и границы проверки описаны в [контракте версионирования](docs/versioning.md).

Настройки инсталляции задаются YAML-файлом на основе [примера](configs/example.yaml). Перед локальным запуском нужно выбрать доступные абсолютные каталоги данных и runtime и настроить путь к собранному helper. Параметр `--config` выбирает файл:

```sh
./bin/gost-restreamer --config /absolute/path/to/config.yaml
```

Файл может содержать только нужные переопределения, например:

```yaml
paths:
  data: /absolute/path/to/local-data
  runtime: /tmp/gost-restreamer
executables:
  helper: /absolute/path/to/gost-restreamer/bin/gost-process-helper
```

Без параметра используются `/etc/gost-restreamer/config.yaml` и, при его отсутствии, `config.yml` в том же каталоге. При наличии обоих выбирается `.yaml` и выводится предупреждение. Встроенные defaults заполняют пропущенные поля, неизвестные настройки останавливают запуск. Изменения файла применяются после перезапуска.

HTTP API доступен под `/api/v1`; стандартные адреса — HTTP `:8080` и ingest `:1935`. Управление работает без авторизации в локальном контуре владельца. Отсутствие NVIDIA или FFmpeg отражается отдельно от готовности управления; для медиазапуска нужны соответствующие компоненты. Полный контракт выбора конфигурации, OBS-маршрута и остановки — в [документации приложения](docs/application-contracts.md).

### Установка на Debian 13

После merge в `develop` CI выдаёт `.deb`, `.tar.gz` и `SHA256SUMS` через GitHub Actions → нужный запуск → Artifacts. Срок хранения — 14 дней; каждый повтор имеет отдельное имя артефакта. GitHub Release для dev не создаётся. Merge в `main` создаёт стабильный тег и **Draft Release** с теми же видами файлов; владелец публикует его вручную после завершения workflow. Повтор CI сохраняет существующий draft и не изменяет опубликованный релиз.

Устанавливайте `.deb` на Debian 13/amd64: проверьте `sha256sum -c gost-restreamer-<Git-версия>-SHA256SUMS`, затем выполните `apt install ./gost-restreamer_<Debian-версия>_amd64.deb` от root. Оба бинарника устанавливаются в `/opt/gost-restreamer`, конфигурация — в `/etc/gost-restreamer/config.yaml`. После настройки службу нужно явно запустить через `systemctl enable --now gost-restreamer`. Обновление останавливает службу; после проверки настроек запустите её вручную. Debian conffiles сохраняют изменённые YAML и unit; SQLite и медиа сохраняются при обновлении и удалении. [Инструкция установки, обновления и диагностики](docs/deployment.md) описывает точные команды и зависимости FFmpeg/NVIDIA.

Для перехода с прежней ручной установки из `.tar.gz` явно остановите `gost-restreamer` перед первой установкой `.deb` и используйте `apt -o Dpkg::Options::=--force-confold install ./<пакет>.deb`, чтобы сохранить локальные YAML и unit. В инструкции приведены [скачивание dev-поставки прямо на VM](docs/deployment.md#скачивание-dev-поставки-прямо-на-vm) и [переход на пакет с проверкой версий и readiness](docs/deployment.md#обновление-и-переход-с-ручной-установки) на примере проверенной версии с T13.

Для отдельного OBS-плагина подготовлены [примеры настройки, команд и REST/SSE](docs/obs-client-guide.md). OBS использует один штатный AV1/AAC-выход; группы и независимые назначения обслуживает backend.

Резервное копирование и восстановление из копий отложены по решению владельца. Аппаратная и live-приёмка Debian/NVIDIA/OBS/площадок выполняется отдельно; `PUBLISHING` не подтверждает изображение у зрителя. Переключение заглушки сохраняет исправные соединения работающего процесса; падение процесса, VM или внешней сети их не сохраняет.

### Медиапроверки с FFmpeg

Обязательные проверки Go работают без FFmpeg, GPU и внешних площадок. Для CPU-интеграций нужны `ffmpeg` и `ffprobe` версии `7.1.5`, кодировщики `libaom-av1`, `libsvtav1`, `libx264`, `aac` и протокол `async`.

Запуск в POSIX shell:

```sh
GOST_MEDIA_FFMPEG="$(command -v ffmpeg)" \
GOST_FMP4_FFMPEG="$(command -v ffmpeg)" \
go test -count=1 ./internal/fallback ./internal/media/fmp4 ./tests/integration
```

Короткая проверка структурированного progress штатной файловой команды FFmpeg:

```sh
GOST_MEDIA_FFMPEG="$(command -v ffmpeg)" \
go test -count=1 ./internal/media/ffmpeg -run '^TestFileCommandCPUProgress$'
```

<details>
<summary>Дополнительная аппаратная проверка на macOS</summary>

На машине с доступным VideoToolbox можно явно проверить аппаратное кодирование H.264:

```sh
GOST_MEDIA_FFMPEG="$(command -v ffmpeg)" GOST_MEDIA_VIDEOTOOLBOX=1 \
go test -count=1 ./tests/integration -run '^TestAcceptanceProfileConversionCPUAndOptionalVideoToolbox$'
```

Сценарий использует `h264_videotoolbox -allow_sw 0`; AV1-декодирование, изменение FPS и масштабирование выполняются на CPU. Условия аппаратных проверок описаны в [профиле среды разработки](CODEX_PROJECT.md#среды-разработки-и-локальные-медиапроверки).

</details>
